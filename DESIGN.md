# Design

## 1. Отмена запросов

Для каждого запроса создаётся свой AbortController (src/searchController.ts). При каждом изменении ввода предыдущий запрос сразу отменяется через abort(), не дожидаясь debounce.

В searchCountries сигнал отмены объединён с таймаутом через AbortSignal.any. Отмена своего запроса приходит как AbortError и пользователю не показывается. Таймаут приходит как TimeoutError и показывается как ошибка с кнопкой "Повторить". Их различает функция classifyError.

Флаг актуальности не использовался, потому что он только скрывает старый ответ, а запрос при этом продолжает выполняться. abort() обрывает запрос по-настоящему, и старые данные не доходят до экрана. Это проверено тестом в src/searchController.test.ts.

## 2. Debounce

Выбрана задержка 300 мс (DEBOUNCE_DELAY_MS). Между нажатиями клавиш обычно проходит от 100 до 250 мс, поэтому во время набора запросы не отправляются. Без debounce запрос уходил бы на каждую букву. При слишком большой задержке поиск казался бы медленным.

## 3. Сложность

mapCountryResponse проходит по массивам languages, currencies и borders по одному разу, поэтому сложность O(L + C + B). Для n стран в searchCountries получается O(n * (L + C + B)).

## 4. Чистый код

Каждый файл отвечает за одну задачу: запрос, преобразование данных, тип ошибки, логика поиска или работа с DOM.

Логика поиска в searchController.ts не зависит от DOM и тестируется без браузера.

mapCountryResponse и classifyError сделаны чистыми функциями.

Вместо магических значений используются константы: DEBOUNCE_DELAY_MS, REQUEST_TIMEOUT_MS, NOT_FOUND_STATUS, API_URL, NO_DATA.

Повторяющийся код вынесен в функции isDomExceptionNamed, createElement и createFlag.
